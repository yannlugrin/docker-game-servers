## 2. Findings

**1. Minor — Rule 2 / Rule 3 (`PROMPT.md` ~lines 126–137, 194–203).** The *check* sweeps "the whole working tree" with exactly one standing exception, `.claude/spec-work/`. The specification documents get explicit protection ("the lint bends to them and never the reverse"), but `.claude/refs/image-contract.md` — tracked, 506 lines, operator-supplied — gets neither an exclusion nor the lint-bends treatment. Rule 3 forbids sweeping, compacting, folding, or deleting a reference but never says "never edit," so an implementer whose markdown lint flags the file can literalistically "fix" it — quiet mutation of operator input, the exact shape the refs rule exists to prevent — while another implementer logs an exclusion. Direction: extend the lint-bends/never-edit treatment (or the standing exclusion) to `.claude/refs/` explicitly, as was done for the specifications.

**2. Minor — Rule 2 (`PROMPT.md` ~lines 99–104) vs `project-zomboid/SPECIFICATIONS.md` §6.** The parenthetical "they are a recommended default — a documented replacement is a legitimate, logged deviation" is true at root §5.5 tier, but PZ §6 states flatly "Both static clients of root §5.5 ship" — for the first image the adoption is already decided in the specification, so replacing a client there is a rule 1 spec conversation, not a rule 4 within-latitude logged deviation. A harness-planning reader of rule 2 could reasonably conclude the opposite. Direction: scope the parenthetical ("where the per-game specification has not already decided adoption").

**3. Minor — First task, closing paragraph (`PROMPT.md` ~lines 654–656).** "Triage its findings — accept, reject with reason, or genuinely my call — and present the triage together with the plans" leaves open whether *accepted* findings are applied to the plans (and committed) before presentation or merely listed as accepted-pending. Two reasonable implementations hand the operator observably different artifacts: amended plans versus original plans plus a to-do. Direction: one sentence fixing whether acceptance means fix-then-present.

**4. Minor — Intro (`PROMPT.md` ~lines 24–27) vs Rule 3 (~lines 167–168).** The intro's shorthand — "the other image tracks' [specifications are read] not at all" — contradicts the rule it cites, which loads other tracks' files "when the current step names a cross-track dependency on them." Rule 3 clearly governs, but the intro is the first thing read and states an absolute the rule immediately relaxes. Direction: align the intro clause ("only via a named cross-track dependency" rather than "not at all").
